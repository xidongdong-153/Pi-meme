# Skill Creator

创建或更新包含 `SKILL.md` 的技能目录，使 Agent 能在指定任务中读取必要说明、调用辅助脚本并找到参考资料。

本文件改编自 OpenAI Codex 内置 skill-creator，保留其编写原则，按 pi-meme 的资源路径、权限和调用方式调整。许可证见 [license.txt](license.txt)。

## 编写原则

- 只写会改变 Agent 决策的信息。删除通用常识、重复要求、无关示例和假设性边界。
- 保留用户指定的目标、产品、位置和授权范围。技能不能扩大任务，也不能替用户授权外部写入。
- 按风险决定步骤细度。开放任务说明完成结果和判断条件；容易误操作的流程才使用固定步骤、脚本和严格参数。区分实际要求与可选建议。
- `name` 和 `description` 会先进入技能列表。描述实际触发场景，只有容易误用时才补排除条件。
- 把目的、必要约束和参考资料入口放在 `SKILL.md`。仅某种模式需要的大段说明放在 `references/`，到用时再读取。
- 技能应能独立使用。只有当前流程确实需要、目标环境实际提供时，才依赖其他技能或工具。

## 文件结构

```text
skill-name/
├── SKILL.md                 必需：技能名称、触发描述和正文
├── scripts/                 可选：需要重复执行的辅助脚本
├── references/              可选：按当前任务读取的资料
└── assets/                  可选：生成结果需要的模板、图片等文件
```

只创建有实际用途的目录和文件。短技能可以只有 `SKILL.md`。不默认添加 README、安装说明、更新历史或重复速查表。

### SKILL.md

文件以 YAML frontmatter 开头，至少包含 `name` 和 `description`：

```markdown
---
name: report-editor
description: 编辑业务报告中的正文和表格，用于按现有模板更新数据、修改结论或修正格式。
---

# Report Editor

编辑前读取用户提供的报告和模板。涉及表格时读取 references/tables.md。
```

- 名称只用小写字母、数字和连字符，长度为 1 至 64 个字符；不以连字符开头或结尾，不使用连续连字符。
- 技能目录与 `name` 相同，除非用户明确要求保留既有目录。
- 描述不超过 1024 个字符。写明触发场景，具体流程放正文。
- 保留已有的有效 frontmatter 字段。`allowed-tools` 是兼容元数据，不会扩大 pi-meme 的执行权限。
- 正文说明结果、必要上下文、执行边界和参考文件。不要为了统一样式强制固定章节或步骤数量。

### 脚本

当同一逻辑会反复重写，或确定性执行能明显减少错误时，放进 `scripts/`。修改脚本后实际运行，检查输出与副作用。

脚本必须写明运行时、参数和输出文件。只依赖目标环境已有的程序，不假设用户安装了 Python、Node.js、Pi CLI 或额外库。先检查运行条件，再决定是否使用辅助脚本；没有 Node.js 时，用已有的 read、write、edit 工具编写 Markdown 并按下列清单核对。脚本开始执行后出错时，说明失败步骤和当前结果，不静默改换实现。

### 参考资料

把某种操作才需要的 schema、API 用法、业务规则和详细示例放进 `references/`。正文链接到文件，并说明何时读取。

信息只保留一份，不把整份参考资料复制回入口。大文件可以加目录和搜索关键词。删除旧资料前检查它的调用位置和用途。

### 生成结果使用的资源

`assets/` 放模板、图片、字体和需要复制到交付结果的文件。它们不是默认加载到上下文中的指令。只在当前任务需要时检查内容。

## 创建或更新

### 1. 确定范围和输出位置

- 用户已说明任务时直接执行；只有缺失信息会影响结果或产生返工时才提问。
- 更新已有技能时先读取该技能及本次涉及的资源，只修改当前任务需要的部分，不重新初始化目录。
- 用户指定输出位置时保留该位置。未指定时，在当前工作区 `pi/skills/<skill-name>/` 生成可审阅的源码；创建目录前检查已有内容，不能覆盖同名技能。
- pi-meme 应用内置技能位于 `<Host 数据根>/pi/builtin-skills/`，属于应用资源，不能由本技能直接修改或覆盖。需要变更内置技能时，修改对应仓库源码并经过应用构建。
- 项目 `.pi` 和 `AGENTS.md` 是只读输入，不往其中写入生成结果。
- 全局安装位置为 `<Host 数据根>/pi/skills/`；默认数据根是 `~/.pi-meme`，可由 `PI_MEME_DATA_ROOT` 修改。创建源码不等于完成安装，不在未授权时复制到 Host 数据目录或更改资源配置。
- 会话处于规划模式、只读权限或路径不允许写入时，只提供可执行的文件方案，不切换权限、不执行写入、不绕过 Host 限制。

### 2. 选择必要资源

根据实际请求决定是否需要辅助文件：

- 重复处理同类文件：考虑脚本，明确输入、输出和错误行为。
- 需要固定模板：把模板放 `assets/`，说明哪些部分保留、哪些部分修改。
- 依赖业务约束或数据结构：把经过核查的资料放 `references/`。

没有具体用途就不创建对应目录，也不添加占位文件。

目标环境有 Node.js 时，可使用本技能目录下的初始化脚本：

```bash
node scripts/init-skill.mjs report-editor --path <已授权输出目录>/pi/skills
node scripts/init-skill.mjs report-editor --path <已授权输出目录>/pi/skills --resources references
```

命令中的 `scripts/` 相对于本技能目录，运行前换成绝对路径。脚本不覆盖已有目录，只生成 `SKILL.md` 和所选资源目录；完成生成后的 TODO 再交付。无 Node.js 时按同样的目录结构直接创建文件。

### 3. 编写入口和指令

先写简短、可区分的触发描述，再写其他 Agent 完成任务所必需的说明。

- 不把一个示例、一次失败或个人偏好扩展为所有任务都必须遵守的规则。
- 重试和外部写入流程写明停止条件；失败时报告具体步骤、原因和当前结果。
- 支持多种较复杂模式时，入口说明选择条件，各模式的步骤放独立参考资料。没有实质分支时不增加路由层。
- 引用相对路径时，以 `SKILL.md` 所在目录为起点；执行命令时换成实际绝对路径。
- 避免要求目标环境没有的 Codex 工具、账户连接或 UI 能力。

### 4. 选择调用方式

默认允许 Agent 根据描述自行选择技能。用户明确要求只能显式调用时，在 frontmatter 加入：

```yaml
disable-model-invocation: true
```

pi-meme 输入框可以通过 `$` 选择技能；Pi 原生命令为 `/skill:<name>`。显式调用限制由 Pi 的 frontmatter 字段决定，不能用 Codex 专有的 `agents/openai.yaml` policy 代替。

已有技能的调用策略保持原样，除非用户要求更改。涉及敏感操作时，保留正常发现方式，在实际写入前遵守权限与授权边界。

需要兼容其他 Agent 产品的 UI 元数据时，读取 [references/ui-metadata.md](references/ui-metadata.md)。普通 Pi 技能不必创建 `agents/`。

### 5. 检查并交付

目标环境有 Node.js 时，运行基础检查：

```bash
node scripts/quick-validate.mjs <技能目录>
```

该脚本仅检查 frontmatter 中的名称和描述、目录名称及未完成占位符，支持普通字符串、单引号、JSON 兼容的双引号和 `|`、`>` 多行描述。它不解析完整 YAML，也不能证明技能决策正确。复杂 YAML 字段应按目标加载器检查；无 Node.js 时直接按以下清单核对。

- 检查 frontmatter、名称、描述和目录是否匹配。
- 删除初始化说明、未完成占位符、无用资源与失效引用。
- 核查引用文件实际存在，命令参数与脚本一致；实际运行新增或修改的脚本。
- 检查指令是否保留用户意图、是否依赖真实存在的工具、是否在错误处给出明确动作。
- 交付技能源码位置、完成的内容和验证结果。没有安装或刷新验证时，明确说明技能尚未进入应用资源列表。

验证应检查可观察结果或重要边界，不写只匹配生成措辞、章节或正则表达式的测试。

## 独立行为验证

技能流程复杂、存在写入风险，且可使用子代理时，可以在隔离临时工作区做独立验证。普通创建或小修改不默认需要此步骤。

给验证 Agent 一个真实请求、技能和完成任务必要的原始材料，不提供预期答案、疑似问题或修复方案。限制可用路径和副作用，检查它实际生成的文件和结果，只修正已观察到的问题。验证需要额外授权、外部生产系统写入或明显成本时，在执行前说明并取得所需授权。

根据实际使用结果修正技能；优先改具体错误，不为每次观察累积一套通用规则。
