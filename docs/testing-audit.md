# 测试审查

本文记录原有测试的处理位置。用例迁移不表示执行已通过；执行状态以统一入口写入的 JSON、日志和 E2E trace 为准。

## 清单与判定

原有 149 个常规测试文件与 2 个独立打包测试均有下表对应记录。当前登记 191 个测试文件：unit 73、component 11、integration 87、e2e 15、artifact 5。

保留的测试验证公开输入和可观察结果：状态投影、参数校验、目标隔离、持久化、真实协议、Worker、SDK、插件和权限边界。跨包覆盖可以承担业务包的集成验证，不以每个包都有测试文件为目标。

组件测试验证真实挂载、effect、点击、键盘、失败提示和回调。保留的 SSR 测试只用于初始结构、只读边界、可访问属性和消息展示契约；它们不代表状态更新或布局已验证。布局、焦点、图片、原生键盘与对话框由 E2E 验证。

## 运行边界

所有模型请求只发往本地假服务。文件、凭据、会话和工作区放在临时目录；测试结束释放 Host、Worker、PTY、浏览器和目录。新增完整流程使用状态条件与假模型屏障同步。既有 SDK、并发回归仍保留短轮询和反例观察窗口，计时与动画测试保留必要等待；不通过增加固定延时掩盖失败。

Vitest 默认保持文件隔离，完整运行限制四个 worker；Playwright 默认一个 worker、零自动重试。真实 macOS 产物不启用 Node 调试 Fuse；缺少产物会失败。Linux 和 WSL 的平台条件会显式报告跳过，不能算作相应平台已验证。

命令与选测表见 [测试](testing.md)。
